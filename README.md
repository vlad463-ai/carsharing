# Carsharing

Приложение для Windows на .NET 8 / MAUI 8.0.100. Откройте `CarsharingApp/CarsharingApp.sln` в Visual Studio с установленной рабочей нагрузкой .NET MAUI.

Windows-проект настроен на запуск без MSIX (`WindowsPackageType=None`, профиль запуска `Project`), поэтому установка пакета для запуска не требуется.

## Сборка и тесты

```powershell
dotnet workload install maui-windows
dotnet build CarsharingApp/CarsharingApp.sln
dotnet test CarsharingApp/CarsharingApp.sln --filter 'TestCategory!=Database'
```

Модели и репозитории компилируются в `CarsharingApp.Core`, поэтому тесты бизнес-логики не зависят от запуска MAUI. Исходные тестовые проекты сохранены в решении.

## Подключение к PostgreSQL

Все экраны используют одну переменную окружения `CARSHARING_CONNECTION_STRING`. Задайте её перед запуском Visual Studio или приложения, например:

```powershell
$env:CARSHARING_CONNECTION_STRING = 'Host=localhost;Port=5432;Database=Carsharing;Username=postgres;Password=<ваш пароль>;Timeout=5'
```

Без переменной используется локальный сервер, база `Carsharing`, пользователь `postgres`, без пароля в исходном коде. Для сервера в учебной сети укажите его адрес и свои реквизиты в этой переменной. Приложение не создаёт и не изменяет схему автоматически.

`База данных/Carsharing.sql` — архив PostgreSQL custom format, несмотря на расширение `.sql`; восстанавливайте его через `pg_restore`, а не открывайте как SQL-скрипт.

## Проверки с базой данных

Создайте отдельную тестовую БД и восстановите в неё схему:

```powershell
createdb -U postgres carsharing_test
pg_restore --exit-on-error --schema-only --no-owner --no-privileges -U postgres -d carsharing_test 'База данных/Carsharing.sql'
psql -U postgres -d carsharing_test -v ON_ERROR_STOP=1 -f 'База данных/Migrations/001_documents_notifications.sql'
$env:CARSHARING_TEST_CONNECTION_STRING = 'Host=localhost;Database=carsharing_test;Username=postgres;Password=<тестовый пароль>'
dotnet test CarsharingApp/CarsharingApp.sln
```

Эти тесты создают и удаляют свои записи; используйте отдельную тестовую базу. Без переменной проверки категории `Database` пропускаются. GitHub Actions проверяет сборку Windows и операции с отдельным PostgreSQL 16, восстановленным из схемы репозитория.

## Работа приложения

После регистрации войдите в аккаунт. На странице автомобилей доступны поиск, бронирование и отзывы; в меню — профиль, история, текущая поездка и выход. Все операции используют вошедшего пользователя и выбранный автомобиль. Поездка начинается в пределах времени активной брони, завершение рассчитывает стоимость по тарифу автомобиля и закрывает бронь. Повторное завершение не создаёт второй платёж. Платёж записывается в учебную БД; интеграции с банковским сервисом нет.

## Уведомления и документы — issues #39–44

После обновления базы выполните миграцию один раз (повторный запуск допустим):

```powershell
psql -U postgres -d Carsharing -v ON_ERROR_STOP=1 -f 'База данных/Migrations/001_documents_notifications.sql'
```

Миграция добавляет единственный комплект документов на пользователя, допустимые статусы, номер версии комплекта и таблицу сотрудников. Она останавливается при дубликатах или неизвестных старых статусах, не удаляя записи. Для тестовой базы выполните ту же миграцию после восстановления дампа. В GitHub Actions это уже включено.

- **Уведомления:** кнопка в меню автомобилей или в профиле. Список содержит только записи вошедшего пользователя, новые расположены первыми и выделены цветом. Нажатие отмечает запись прочитанной; кнопка «Обновить» получает новые события.
- **Мои документы:** профиль → «Мои документы». Выберите фото паспорта и прав (JPEG/PNG, до 10 МБ каждое), затем «Отправить на проверку». При первой отправке нужны оба фото. После замены одного или обоих фото статус возвращается к «на проверке».
- **Проверка:** сотрудник открывает профиль → «Проверить документы пользователей», просматривает обе фотографии и выбирает решение. Пользователь получает уведомление, а статус виден в профиле и на экране документов после обновления или повторного открытия.
- Повторное решение не дублирует уведомление. Старую версию фотографий нельзя одобрить после замены. Сотрудник не может проверять собственный комплект.

Право сотрудника назначается администратором БД, а не через обычный интерфейс. Для уже существующего аккаунта:

```sql
INSERT INTO staff_users(user_id)
SELECT id FROM users WHERE login = 'denis'
ON CONFLICT DO NOTHING;
```

В приложении нет функции самостоятельного назначения сотрудником. Проверка роли выполняется и в репозитории, а не только при показе кнопки. Как и остальное учебное приложение, клиент подключается к PostgreSQL напрямую; учётная запись администратора БД имеет полный доступ к данным независимо от роли пользователя приложения.

### Хранение фотографий

В БД сохраняются только пути. Само приложение копирует выбранные изображения под случайными именами в `%LOCALAPPDATA%/Carsharing/Documents/<userId>`. Исходные фото не удаляются. Ошибка сохранения в БД удаляет только новые незарегистрированные копии. Старые версии остаются в каталоге, чтобы замена не ломала уже открытый просмотр; автоматической очистки архива пока нет.

Если пользователь и сотрудник работают на разных компьютерах, задайте **одинаковую доступную обоим папку**, например защищённый общий каталог:

```powershell
[Environment]::SetEnvironmentVariable('CARSHARING_DOCUMENTS_DIRECTORY', '\\server\CarsharingDocuments', 'User')
```

Настройте права доступа к этому каталогу для нужных пользователей Windows. Не помещайте паспортные фотографии в репозиторий. Перезапустите приложение после изменения переменной. Для уже сохранённых локально фотографий потребуется повторная загрузка в общий каталог.

### Проверка вручную

Используйте искусственные изображения вместо настоящих документов:

1. В обычном аккаунте загрузите оба изображения. Убедитесь, что в профиле указан статус «на проверке».
2. В сотруднике откройте комплект, просмотрите фото и одобрите его.
3. В обычном аккаунте обновите статус и откройте уведомления. Убедитесь, что появилось новое уведомление; нажатие снимает выделение и уменьшает счётчик непрочитанных.
4. Замените одно изображение. Убедитесь, что комплект остаётся один, а статус снова «на проверке».
5. Откройте комплект у сотрудника, затем замените фото у пользователя. Решение по старой открытой версии должно потребовать обновления списка.

Автотесты покрывают выборку только своих уведомлений, сортировку, прочтение и счётчик, FK документов, замену, конкурентные загрузки, права сотрудника и их отзыв, версии комплекта, уведомление о решении и ограничения файлов.
